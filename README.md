# CardsMP

CardsMP is a multiplayer browser card game built with Vite, TypeScript, Express, and Socket.IO. The frontend is a static app, and the backend owns the real-time game state and room events.

Maintained by @lualum and @GeniusBlobby.

The current production setup is split:

- Frontend: GitHub Pages at `https://cardsmp.github.io/`
- Backend: VM-hosted Socket.IO server at `https://cardsmp.duckdns.org`

## Local Development

Use pnpm, matching the Docker and GitHub Actions setup:

```sh
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm install
pnpm run dev
```

Local dev starts both processes:

- Vite frontend: `http://localhost:3000`
- Backend server: `http://localhost:8000`

The Vite dev server proxies `/socket.io` to the backend, while the client can also connect directly to port `8000` when running on the local frontend port.

## Scripts

```sh
pnpm run dev
```

Starts the backend watcher and Vite dev server together.

```sh
pnpm run build:pages
```

Builds the static frontend for GitHub Pages. It writes `dist/public`, creates `404.html` for direct room links, and adds `.nojekyll`.

```sh
pnpm run build:backend
```

Builds the shared package and backend server for the VM.

```sh
pnpm run build
```

Builds shared code, frontend, and backend.

```sh
pnpm run start
```

Runs the backend server only. This is the production VM path.

```sh
pnpm run start:all
```

Runs the backend plus `vite preview`. This is mostly useful for checking a combined local production build.

## Deployment

### GitHub Pages Frontend

The frontend deploys from `.github/workflows/pages.yml`.

Repository setup:

1. Go to `Settings -> Pages`.
2. Set `Build and deployment -> Source` to `GitHub Actions`.
3. Push to `main`.

The workflow installs dependencies with pnpm, runs:

```sh
pnpm run build:pages
```

and deploys `dist/public` as the Pages artifact.

Default frontend build environment:

```txt
VITE_BACKEND_URL=https://cardsmp.duckdns.org
VITE_BASE_PATH=/
```

`VITE_BACKEND_URL` is the Socket.IO backend URL compiled into the browser app. `VITE_BASE_PATH=/` is correct for `https://cardsmp.github.io/`.

### VM Backend

The backend deploys from `.github/workflows/deploy.yml`.

Required GitHub secrets:

```txt
VM_HOST
VM_USER
VM_SSH_KEY
```

On push to `main`, the workflow SSHes into the VM, pulls the current repository, rebuilds the Docker image, and runs:

```sh
docker compose up -d --build --remove-orphans
```

The Docker container builds only the backend and exposes port `8000` inside the `web` Docker network.

Default backend environment:

```txt
NODE_ENV=production
PORT=8000
FRONTEND_ORIGIN=https://cardsmp.github.io
```

Your VM reverse proxy should route `https://cardsmp.duckdns.org/socket.io` to the backend container on port `8000`.

## Configuration Points

- `shared/src/config.ts`: shared local ports.
- `public/src/session.ts`: chooses the Socket.IO backend URL.
- `public/src/app-paths.ts`: keeps room links and assets correct for the frontend base path.
- `vite.config.ts`: Vite build base, static card/image copying, and local Socket.IO proxy.
- `server/src/index.ts`: Express/Socket.IO server, CORS origins, and backend-only production behavior.

The backend allows `FRONTEND_ORIGIN` and comma-separated `ALLOWED_ORIGINS` overrides for Socket.IO CORS if the public frontend URL changes.

## Project Layout

```txt
public/       Frontend HTML, TypeScript, styles, and card assets
server/       Express and Socket.IO backend
shared/       Shared game, room, player, card, chat, and config code
scripts/      Build helper scripts
dist/         Generated build output
```

## Notes

- Do not commit `dist/`; it is generated by the build workflows.
- The frontend talks to the backend through Socket.IO events, not REST endpoints.
- GitHub Pages cannot serve the backend. It only hosts the static frontend.
- Direct room links work on Pages because `build:pages` creates `404.html` as an SPA fallback.
